## Confirmed findings — address first

### A01 — Session invalidation leaves the prior user's local job history [P1, privacy]

`app/lib/authClient.js:119,133,340,358`; `app/veyrnox/_lib/jobHistory.js:9`; `app/veyrnox/app/library/page.js:86`.

Explicit sign-out clears job history, but `clearSession()` and definitive refresh rejection only call `setSession(null)`. History is stored under one browser-wide key, not a user-specific key. Library renders this cache before its authenticated server listing and preserves queued cache entries when merging. The credits page also reads this local history. A local reproduction confirmed `clearSession()` removes the session while retaining the previous user's prompt history.

Action: scope caches to verified account IDs; clear cached identity data on every logout/invalidation/account change; reset mounted page state; never render another account's cache before identity resolution. Preserve the explicit sign-out fix already present.

### A02 — Upload issuance does not enforce actual storage bytes or reserve slots [P1, abuse/cost]

`app/api/v1/uploads/route.js:30`; `packages/adapters/r2.js:387`; `lib/resolveSource.js:69`.

The PUT signature binds Content-Type and host, not byte length. Declared size is checked before signing, while actual size is inspected only when generation later reads the upload. The ten-object limit is a snapshot, not a reservation; concurrent outstanding URLs can exceed it. A 15-minute URL can be reused. Request quotas limit signing work but do not enforce storage consumption.

Action: enforce actual upload limits at ingestion, reserve outstanding uploads, and apply per-account byte/object budgets with lifecycle cleanup. Do not describe the existing request quota as a storage cap. No oversized production upload was attempted.

### A03 — Validated uploads remain mutable until the provider fetches them [P1, validation integrity]

`packages/adapters/r2.js:387`; `lib/resolveSource.js:41,102`.

Generation validates a range from an object and hands the provider a GET URL for that same key. The client's original PUT URL remains usable for up to 15 minutes. There is no immutable staging copy, version/ETag binding, or one-use write finalization in this path. Content, dimensions or duration can therefore change after validation. This is confirmed from the data flow, not demonstrated against a live provider.

Action: finalize to an immutable object before validation/submission, or bind consumption to the exact validated content/version and prevent subsequent replacement.

### A04 — Anonymous reconciliation RPC performs expensive privileged work [P1, scaling/abuse]

`packages/db/schema/supabase/0072_reconcile_status_rpc.sql`; `.github/workflows/reconcile-watch.yml`.

Production confirms `reconcile_status()` is anonymously executable as SECURITY DEFINER. It recomputes ledger aggregates; application/Worker quotas do not protect direct Supabase RPC calls. The existing migration explicitly records this unresolved cost exposure. There were only 63 ledger rows at the audit snapshot, so present load is small; exposure grows with usage.

Action: move the watcher to narrowly scoped authentication, or have trusted scheduled work populate a cheap snapshot and expose only that. Do not revoke the grant before replacing the monitor. `catalog_watch()` and `applied_migration_names()` are also public but read smaller, bounded metadata; decide their exposure separately.

### A05 — Inbound bodies are buffered without application-level size limits [P1, availability]

`app/api/webhook/stripe/route.js:64`; other webhook route `req.text()/arrayBuffer()` calls; `app/api/v1/generations/route.js:200`.

Webhook routes buffer request bodies before verifying signatures. Generation and other JSON routes parse whole bodies before applying semantic validation/quota. No shared byte-bounded reader or route-specific body ceiling was found. Cloudflare platform limits are not a substitute for an appropriately small JSON/webhook limit.

Action: stream-count bytes with endpoint-specific limits, return 413 when exceeded, preserve exact raw bytes for signature checks, and bound JSON parsing. Check header claims as an optimization, not as the enforcement mechanism. No memory-exhaustion traffic was sent.

### A06 — Outbound deadlines do not cover response bodies [P1, reliability]

`lib/fetchWithTimeout.js:19`; `packages/db/supabase-client.js:69,115,160`; `lib/resolveSource.js:87`.

Timers are cleared when fetch resolves, which is when headers arrive. Subsequent `json()`, `text()` or `arrayBuffer()` reads are no longer covered. Local reproduction: a 40ms configured timeout allowed a delayed JSON body to finish after 274ms without aborting. Some range readers also accept a full 200 response and buffer it, so range fallback needs explicit body bounds.

Action: maintain deadlines through body consumption and stream limits; propagate cancellation; test stalled/oversized bodies, not just delayed headers.

## Confirmed product and operational gaps

### A07 — Refunded generations can still display a debit [P2]

`app/veyrnox/app/credits/page.js:62,148`; `app/api/v1/jobs/[id]/route.js:94`.

The API returns `refunded`, but history enrichment copies only `state` and `error_code`; rendering then checks `l.refunded === true`. Normal cached submissions have no refund flag, so a refunded job can show a negative amount. Forward the authoritative refund state and add a UI-level regression. Do not infer money movement solely from a failed state.

### A08 — “AUTO-SAVING” is inaccurate and drafts are lost [P2]

`app/veyrnox/app/create/page.js:54,308`.

The prompt lives in React state; no draft persistence is wired to the advertised status. Live Chromium test: enter a unique prompt, reload, and the hardcoded Tokyo prompt returns. Implement account-scoped draft persistence/status or remove the claim. Include model/source/consent handling in the draft policy.

### A09 — Customers cannot view a complete authoritative credit ledger [P2]

`app/veyrnox/app/credits/page.js:53`; `app/api/v1/top-ups/route.js:178`.

Recent generations are reconstructed from the current browser's last 15 cached jobs. Top-up history is capped at 20 with no pagination. Grants, expiry, corrections, all refunds and older activity are not represented as a complete server-backed statement, despite marketing references to reading credit history.

Action: provide owner-scoped, paginated ledger/Top-up history, clearly distinguish debit and refund entries, and make it work across devices. The main Library already has a server listing; do not confuse this gap with the older fixed Library-list issue.

### A10 — Account/security self-service remains incomplete [P2, product decision]

`/app/account` is a live 404. `MfaPanel` is mounted on the admin page. GDPR requests currently go through email, as the legal page accurately states.

Provide a discoverable account page with ordinary-user MFA, password/account recovery management, active-session controls and clear export/deletion requests/status. Export/deletion must respect ledger retention and revoke sessions appropriately. Missing self-service is a product/support gap, not proof the existing email process violates law.

### A11 — Asset-expiry UI remains opt-in [P2]

`app/veyrnox/app/library/page.js:58,62,413`.

The expiry component is still behind `localStorage.veyrnox_asset_expiry === '1'`. Most users do not receive the intended in-product expiry notice, although automatic retention is active and the privacy notice states 90 days.

Complete the existing rollout/observation gate, then enable notices for ordinary users. Keep presigned-link refresh and actual retention separate; link refresh is already implemented.

### A12 — Attribution storage exceeds the notice's stated purposes [P2, privacy review]

`app/veyrnox/_lib/utm.js:16,64`; `app/veyrnox/_components/SiteChrome.js:24,158`.

The storage notice describes session/theme and necessary storage, but every page captures UTM data, gclid/fbclid and an external referrer into persistent localStorage without an expiry or opt-in gate. Live test confirmed a UTM record is stored. No transmission by this module was found; do not call this third-party tracking or data sale.

Action: remove unused attribution, or document purpose/retention and obtain a jurisdiction-appropriate consent assessment. Do not assume marketing attribution is necessary for authentication.

### A13 — Legal-page version metadata is stale [P2]

`app/legal/_lib/Legal.js:11` still says 13 September 2026 while terms now contain changes shipped on 24 September, including 10 signup credits. Update per-document dates/versioning and keep material-change notices consistent with the Terms' own promises.

### A14 — Dialog keyboard behavior is inconsistent [P2, accessibility]

`app/veyrnox/_components/ConfirmDialog.js:19,33`; `app/veyrnox/_components/EditSheet.js:37,89`.

ConfirmDialog sets initial focus and handles Escape but has no focus containment/restoration. EditSheet handles Escape but lacks initial focus/containment/restoration. `aria-modal` alone does not implement these behaviors. AuthGate already has a stronger focus implementation.

Action: reuse a tested accessible dialog primitive, including focus trapping, restoration, inert background and busy-state behavior. Validate authenticated editor flows with keyboard/screen reader. The simple public-page DOM checks are not an accessibility certification.

### A15 — Authenticated credit-pack reads remain an uncached DB path [P2]

`app/api/v1/credit-packs/route.js` selects credit packs on every request without a quota/cache, while `/api/credit-packs` has a five-minute cache. Consolidate the safe public catalog read or add equivalent caching/quota. Cheap identity-only endpoints should be evaluated proportionately rather than given a database limiter by default.

### A16 — Reap-queue bookkeeping ignores HTTP failures [P2]

`lib/assetReap.js:40,46,71`.

After deleting an object, `markSuccess()` returns an HTTP Response whose `ok` status is not checked before incrementing deleted count. Failed PATCH requests are similarly not inspected. A backend rejection can leave queue state unchanged while reporting apparent progress. Check all mutation responses and surface retryable bookkeeping failures. Current queue is empty; this is a code defect, not evidence of a current undeleted backlog.

### A17 — Worker recovery needs explicit dead-letter and freshness alerts [P2]

`worker.js:31`; `lib/assetReap.js:20,32`; `lib/topUpBackfill.js`.

Worker tasks largely emit console logs; reaping stops selecting records after eight attempts. Reconciliation cannot detect every stuck provider job, failed deletion, operator-refund queue or missing cron invocation. Existing GitHub reconciliation alarms and DB cron success are valuable but insufficient for all these cases.

Action: publish last-success timestamps, queue age/depth, exhausted retries, payment flags and recovery lag to alerts with an owner/runbook. Verify any dashboard-only alerts before declaring them absent. No current exhausted reap entries or flagged orders were found.

### A18 — Retired LemonSqueezy paths remain in the deployed source [P3, cleanup]

`app/api/webhook/lemonsqueezy/route.js`; `packages/adapters/lemonsqueezy.js`; stale comments in credit-pack routes and historical ADRs.

Stripe is the active provider, but legacy webhook/adapter code remains and can become active if old secrets are still configured. Establish whether historical refunds/disputes require compatibility, then disable/remove unnecessary routes and revoke obsolete credentials. Do not delete historical accounting records or assume legacy secrets are currently installed.

### A19 — Database indexes and Auth scaling configuration need review [P3]

Production advisor reports five unindexed foreign keys: `account_actions.top_up_id`, `top_up_flagged_orders.user_id`, `top_up_order_collisions.credited_top_up_id`, `top_up_order_collisions.top_up_id`, `top_ups.pack_id`. Assess query/delete plans before adding indexes. Auth uses an absolute ten-connection allocation; revisit before increasing compute or traffic. Seven unused-index notices are not an instruction to remove integrity/rare-path indexes.

[Foreign-key advisory](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys)

## Verification or owner decisions — not proven live defects

### V01 — Real edge/WAF coverage

ADR-0039's Worker binding cannot prevent Worker invocation cost and is approximate per location. Cloudflare Access was observed working. Inspect the actual zone rules, alternate hostnames/workers.dev routes, general API/body abuse limits and webhook exceptions before declaring the edge layer complete. Do not claim a zone rule is absent solely because it is not in git.

### V02 — Backups and restore readiness

Verify backup/PITR entitlement, retention, encryption/access, RPO/RTO and a recorded restore drill. Repository planning references are not evidence of current configuration. Include object storage and the append-only ledger in disaster-recovery procedures.

### V03 — Credential lifecycle and session threat model

Verify whether the runtime has moved from the legacy service-role JWT to an sb_secret key, least-privilege scopes and rotation ownership; secret values were not read. Review access-token lifetime/session-revocation requirements. Middleware verifies JWTs offline, and localStorage tokens coexist with script-src unsafe-inline. Current sink gates reduce risk; no XSS was demonstrated. Stronger CSP/session storage is an architecture decision, not a one-line header change.

### V04 — Provider, payment and legal evidence

Independently verify live Stripe/Merchant-of-Record account settings and refund/dispute runbooks, current provider licences/cost assumptions, processor agreements and international-transfer documentation, actual retention/log windows, and legal review of content provenance/moderation disclosures. Existing policy assertions are not documentary proof. No compliance violation is concluded here.

### V05 — Authenticated end-to-end QA and performance baselines

Automate mobile/desktop sign-up, confirmation, OAuth/passkey/MFA, checkout-return/recovery, generation success/refund, upload rejection, cross-device history and expired-asset flows in isolated staging. Add body-stall, account-switch and refund-render cases to CI. Capture field Core Web Vitals and representative load/cost budgets; the 390px public-page smoke is not a full performance study. No real purchase or paid generation was made for this audit.

## Caveats and non-findings

- The `21st` CLI and `.21st/design.json` were unavailable in this checkout. Review used actual Chromium behavior and source instead; no deterministic 21st pass is claimed.
- Supabase's 14 “RLS enabled, no policy” notices match service-role/RPC-only tables. They are not demonstrated public data leaks; adding permissive policies to silence them would be wrong.
- Public privileged metadata functions are deliberate. The material concern is the cost of `reconcile_status`, not the mere presence of SECURITY DEFINER.
- `/m/*` is visibly labelled a sample-data design prototype and marked noindex. Its sample balance is not reported as a live-account data defect.
- No critical exploit, ledger drift, current paid-order collision, dependency CVE or public account-data exposure was demonstrated. This statement is scoped to the checks above.
