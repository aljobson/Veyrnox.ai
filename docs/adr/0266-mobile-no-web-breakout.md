# ADR-0266: Mobile stays native for legal, Help and media

Date: 2026-10-27
Status: Accepted (owner, 2026-10-27). Implemented; independently reviewed; checked on the iOS simulator signed in.

The owner requires “nothing to go to web, privacy and everything in help needs to be Mobile native. No web breakout.” Web-only features are hidden until they have native implementations. This decision does not change authentication, consent gating, purchases, restore, or social connection behavior.

The five groups are:

- A: Legal and policy documents use a shared native LegalDocumentView. Signed-in screens push `/legal/[doc]` in the app stack. Sign-in opens a full-height LegalSheet without unmounting sign-in. AI consent replaces content inside its existing Modal; reading or closing legal content never answers the pending consent request. Cross-document links stay in the same presentation with Back navigation.
- B: Help guide destinations use native routes. Unsupported destinations are hidden while the guide remains. MCP no longer links to its website guide. Creator support uses the app's existing support email address.
- C: Film Studio desktop links, Publish ads/commerce/drafts/workflow web fallbacks, editorial series playback, creator workspace and series-management web fallbacks are hidden. Existing screens, reads, editing and uploads remain. Surfaces without an available action explain that the feature is coming to the app, using one shared English key. These capabilities can return as native features later.
- D: Finished job video/audio, stems and review videos use expo-video in place with native controls. Players do not autoplay, begin muted until deliberate playback, and pause on blur/background. Only one stem player is mounted at a time. Images retain their existing rendering. Example source attribution and published post addresses are selectable text.
- E: External system flows remain allowed: Supabase Apple/Google OAuth and Publish network OAuth require provider authentication sessions; OAuth consent returns to the requesting app; Apple/Google subscription management uses the store's management page; email uses mailto; authenticator enrollment uses validated otpauth TOTP URIs. A source guard enumerates exact files and call sites with reasons. No general browser fallback is permitted.

Embedded WebViews for the editor, Oddlings and Turnstile remain in scope of their existing decisions; they do not break out to a browser.

The website is the legal source of truth. `apps/mobile/scripts/sync-web-legal.mjs` reads its six structured documents, eleven locale catalogs, chrome, localized jurisdiction, English supply statement and entity facts without changing website files. Generated data under `apps/mobile/src/lib/legal/generated/` updates with an app release. `--check` and its Jest test fail verification when website data and the committed app copy differ. Literal lazy requires defer locale evaluation; Metro still includes all locales (566,505 bytes of generated TypeScript source before bundle compression).

Native rendering preserves entity and inline slots, headings, lists, emphasis, translated jurisdiction, localized dates, translation notice and English-reading action, the English supply statement, and Arabic numeric isolation. Legal links navigate internally; mail links use mailto; other addresses are inert selectable text. New components use ADR-0264 primitives and tokens. No dependency, native module or plugin is added.


Proof: `cd apps/mobile && npx tsc --noEmit && npx jest --ci && node scripts/gen-en-registry.mjs --check && node scripts/sync-web-legal.mjs --check` passes (223 suites, 4,047 tests).

Review attachments now show a static, labelled load-video poster until tapped. The review response supplies no thumbnail URL, so no thumbnail is fetched or generated. Only the selected attachment mounts a player; selecting another pauses and releases the previous one. Loading does not start playback, and audio stays muted until deliberate native playback. Tests cover initial absence of players, selection, disposal and mute/autoplay behavior.

Legal destinations retain decoded fragments in both route parameters and sheet history. The renderer measures the block with the matching web `attrs.id` relative to its content and scrolls without animation after layout. Missing or empty fragments open at the top. Same-document fragments and the GDPR link to `/legal/privacy#account-deletion` are covered, including sheet Back. The English-reading action retains the section anchor.

Inline legal and sign-in links no longer set `lineHeight: 44`. Deviation: React Native 0.88 inline Text has no supported hitSlop prop, and nested Text padding is not included in its attributed-string layout. Thus normal paragraph line height and guaranteed 44pt inline targets cannot both be provided by these primitives. The app retains normal inline targets and the existing sign-in accessibility actions. Separate visible 44pt link controls would be needed to guarantee that target size; they have not been added as an unrequested redesign. Existing standalone native buttons retain their 44pt targets.

English app-only instructions to use the website were rewritten in ads, approvals, autolists, brand, calendar, chat, cinemaCreator, cinemaUpload, commerce, drafts, inbox, pk, plan, publishWorkflows and reports. The audit checked values for web, website, browser, veyrnox.ai and “on your computer”, excluding harmless product names, file formats, webhooks and explanatory comparisons. No key in `webKeys.json` needed a change. One additional web-shared value is preserved: `helpGuides.content.library.s3.body` is generated by `sync-help-guides.mjs` even though it is absent from `webKeys.json`. Its browser wording describes the web source, not an instruction to leave the app; the existing `presentGuide` override displays `helpGuides.mobile.library.favourites` (this phone) instead. Changing the generated source would fail the agreed synchronization proof, so it remains unchanged. `webKeys.json`, website sources and `en/_order.ts` are unchanged. Unused, unpinned keys removed: `cinemaUpload.series`, `cinemaSeries.watchLabel`, `cinemaSeries.browserNote`, `cinemaSeries.openFailed`, `publishWorkflows.webOnly`, `publishWorkflows.continueWeb`, `publishWorkflows.webFailed`, `mcp.webGuide`. Pinned `cinemaCreator.upload.web`, `ads.continueWeb` and `drafts.openWeb` remain with neutral copy. The English registry was regenerated; its import/spread output is unchanged.
