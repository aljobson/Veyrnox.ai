# ADR-0271: Social Cinema creator depth on the phone

Status: Accepted.

The phone creator workspace supports Series → Season → Episode drafts alongside Film, Short and Trailer roots. All creator tools retain the existing device-upload flag and creator-owner gate. This decision changes neither production flags nor server contracts.

Pure helpers in `apps/mobile/src/lib/cinemaStudio.ts` validate hierarchy, immutable positions, draft bodies, withdrawal reasons and Library import identifiers. Lists request one parent level at a time. Roots preserve the existing draft validation; child bodies omit categories and require a UUID parent and position 1–10000. The editor shows categories for root Series and preserves a child's stored position on edits. Series submit without a local video-ready prerequisite because the server checks all episodes; submission remains root-only. Existing Film, Short and Trailer submission messages are preserved.

Root titles under review or published may be withdrawn with a reason and a title-specific destructive confirmation. Reasons use the server's 3–500 code-point limit. Requests reuse a body key until success or definite refusal, and concurrent confirmations cannot send twice. Success reports only that the title is a private draft again, without refund counts or credit figures. Role and closed-feature responses degrade quietly.

Library import reuses the existing video chooser only when the server enables it and there is no upload, staged file or running transfer. A job's import key survives uncertain failures only; success, definite refusal, successful removal and an empty read/refresh clear it. This prevents reuse of a removed upload's idempotency tombstone. Import safety holds leave device-upload controls available. Library provisioning and processing use the corresponding website messages.

Video-ready Film, Short, Trailer and Episode details may show the automatic JPEG poster frame. The authenticated stream request sends `cache: 'no-store'`, `Cache-Control: no-store` and `Pragma: no-cache`. Only JPEG signatures within 5 MiB are accepted. The data URI exists only in account-keyed component state; late results check creator scope, and expo-image has `cachePolicy="none"`. No poster upload is offered.

Viewer deep links map valid editorial series slugs to the existing series screen and the exact Pass path to Cinema's Profile section. The section parameter is consumed and cleared so a subsequent identical link selects Profile again. No purchasing UI or external purchase link is added.

Website-shared strings are copied byte for byte from the website English catalog, listed in `webKeys.json`, and generated into the ten locale catalogs by `sync-web-i18n.mjs`. Four app-only strings cover titled confirmations, numbered children and position validation; their ten machine translations retain the same slots. The English registry and length reviews are generated by their existing scripts. Native linguistic review remains pending under ADR-0270. Localized numbered labels use locale-appropriate number markers where needed, avoiding English-equal values.

The frozen work order explicitly assigns ADR number 0000. Its whitelist permits only the named mobile files and this ADR. No dependency, server file, migration, flag, upload store, player or association-path change is part of this decision.

## Owner decisions and inspection

- O1: Editorial episodes require either YouTube embedding (a new host, WebView and snapshot IDs, reversing ADR-0240's projection) or migration to Stream. Until that choice is made, the editorial series screen keeps ComingToApp. Database series already play episodes.
- O2: `/social-cinema/*` is absent from the server's `APP_LINK_PATHS`. OS handling of these HTTPS links requires a separate server PR; the phone mapping is ready, as for the existing title/watch routes.
- O3: Library import remains hidden in production until `CINEMA_QUARANTINE_SCANNER_ENABLED` is `"true"`.
- O4: The existing Open running upload link has no parent context. For an episode it reaches detail without `parent` and shows Not available yet. The upload store does not know parents; this limitation is accepted.
- O5: The independent simulator inspector must check whether the native URL cache honors the poster's no-store request. If the response is stored, remove the poster feature rather than changing transport.

## Verification and bounded interpretation

Helper tests pin server body keys, validation, messages and poster transport options. Screen tests cover hierarchy navigation, parent-preserving edits, withdrawal confirmation, import retries/removal, poster rendering and repeated Pass links. Existing creator and translation tests remain required, followed by TypeScript and the full mobile Jest suite and all three catalog checks. Manual inspection uses the consolidated mobile environment and default iPhone 17 Pro; it is not a requirement for the builder's proof.

The child form retains the existing `DraftInput.categories` array internally; empty arrays are accepted and the child request omits the field. Nonempty child categories are refused, matching the server and web. The required existing `LibraryChooser` already has a slide presentation animation. It is reused unchanged because its source is outside this work order's whitelist; no new animation is introduced.
