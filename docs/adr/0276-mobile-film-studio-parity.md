# ADR-0000: Mobile Film Studio control parity

Status: Accepted for implementation in two parts.

The phone Film Studio uses the existing project schema and the web's validation rules. Part A adds setup pickers, autosave, guarded navigation, individual shot and board cards, and sequential stage access. Part B completes stages 5–7, output and revision controls, and account actions. Neither part changes the server, prices, flags or migrations.

FilmSelect wraps the existing PickSheet with labelled 44-point controls. PickSheet's optional noneLabel preserves the Oddlings default; Film Studio passes null and explicitly supplies any required blank model option. Catalog choices use capabilities.inputs and store model IDs. Legacy names and removed models remain visible as unavailable choices and are never silently rewritten. External workflow names stay editable.

Clip lengths come from the selected Studio video model within 10–15 seconds; External supports the full range. Frame formats intersect model aspects with 16:9, 9:16 and 1:1, falling back to those three when the intersection is empty. This deliberately differs from the web selector because both document parsers accept only those three formats. Model changes normalize length and format. Prompt handoff separately checks the actual model aspect list, so the fallback does not promise unsupported generation.

Shot cards allocate the first ID unused by shots, prompts or attempts. The draft ID is sanitized, but only valid, unique IDs without orphaned history replace the stored ID. This is deliberately stricter than the web: an invalid draft shows a field error instead of making the whole studio fail to save. Board scaffolding similarly allocates unique IDs, including within the same scaffold; editing references resets approval to revise. Stages open through the first stage with issues, with Continue available only when the current stage is ready.

Edits debounce for 600 ms. Local save reads back the stored text to detect disk failures despite best-effort cache writes. Workspace loads, edits, timers, flushes and New confirmations capture account ownership and generation. Account changes cancel pending edits and clear the view before reloading. New passes its captured owner to clearStudio and checks the session again after awaiting it. Blur and navigation flush edits, and a failed leave flush offers Stay or Leave without saving.

Cloud saves serialize per owner and film generation at module scope so remounts cannot create duplicate projects. A queued edit uses the preceding save's link and expected revision, and identical retries retain their idempotency key. Completion updates only the link, retaining newer local edits. Clear, open and account changes invalidate stale completions. A cloud-open film is held in memory, and the saved status explains that saving to the account is required to keep it beyond the app session.

The app length-review script now uses the translation test's English fallback for plural forms: the exact English key, or the family's .other when English has both .one and .other. This preserves existing reviews while adding only new expanded strings. New Film Studio messages live in the filmWorkspace area. The frozen order requested filmStudio-prefixed messages in that area, but the existing catalog reader rejects mismatched prefixes; the three new validation messages therefore use filmWorkspace keys instead. Existing locale catalog and length-review files already exceed the 500-line limit and retain their mandated structure; new implementation files remain below it.

Part B uses these shared selectors and helpers for passports, tests and prompts. Its scope includes prompt output, the one-line revision loop and fifteen-miss limit, copying via the host-provided copyText share-sheet helper, aspect handoff, account removal, and conflict actions. Part A introduces no Copy action or clipboard dependency. Part B does not need to revise this ADR.
