# ADR-0321 — Hourly server telemetry, default off

Status: accepted for implementation; owner privacy review pending.

The telemetry enable switch defaults off. The collector's disabled hot path is one cached boolean read, with no clock, parsing, new counter update, logging, fetch or waitUntil; observing off discards previously buffered counters. A control-plane trigger reads runtime switches in waitUntil with a rejection catch, using the exact S3 cache/in-flight promise and its single clock. All consumers together issue at most one successful read per isolate per 15 seconds; failures back off five seconds. This is a continuous steady control-plane cost under traffic: one runtime_switches read per active isolate per 15 seconds even when telemetry is off, because DB-only switches otherwise cannot be discovered. Idle isolates do not poll. A fresh shared cache skips the DB read and returns a resolved promise; there is no second read or additional telemetry polling timer. This is an explicit deviation from a literal “no activity whatsoever while off”: a cold isolate cannot discover a changed DB-only switch without a read. No visitor data enters that refresh and telemetry never awaits refresh or ingest on the request path. Kill-gated writes separately await that shared refresh for at most approximately 400 ms when expired, as documented in ADR-0319. The first cold request is not counted.

Enabled collection records successful HTML GET responses as views, excluding RSC/prefetch. Route counts include responses reaching the Worker hook; early transport redirects, showcase responses, rate-limit refusals, upstream cache hits and client-only navigation are excluded. Counts are not unique visitors or complete business analytics. Latency covers bounded-body/admission/handler execution, not the earlier Worker gates.

Only hourly aggregates leave the isolate: generated fixed route patterns (dynamic segments become :id; unknown becomes other), HTTP method/status class, capped latency sums/maxima, country from cf-ipcountry only, broad device class and a finite public referrer-host allowlist. Unknown referrers become other; no full referrer, query, URL, IP, cookie, user ID or UA string is stored. UA is classified in memory and immediately discarded. RPC validates exact shapes, finite dimensions, numbers and batches of at most 500. Unknown string path/route patterns collapse to other per row, so inventory/migration deployment skew does not discard an entire batch. Wrong types, empty/over-512-character patterns and invalid numeric bounds still reject the batch. An exact inventory/SQL allowlist test catches drift, excluding the generic /api/v1/:id* 404 catch-all that the collector never emits. Tables have forced RLS and no direct service-role grant. Admin reads require the respective role permission.

Counters are bounded at 500 tuples and overflow collapses to other. A response triggers a flush at most once per 60 seconds using waitUntil; there are no orphaned timers. The first enabled response can flush immediately. After a flush, another request at least 60 seconds later is required to send buffered counts. A transition to off observed at request start or finish clears pending counters; a queued batch also checks the cached switch before sending. An already dispatched batch cannot be recalled; the ingest RPC rechecks the DB switch. Idle isolates do not flush until another response; termination and failed batches can lose counts. Failed ingest logs one fixed message and drops that batch, without unsafe additive retries. The next ingest opportunistically removes rows older than 90 days; with collection disabled and no ingest calls, pruning waits until ingest resumes. Endpoint totals cover the current hour and previous 23 hours.

Reports suppress each hourly traffic dimension tuple with fewer than five views, and each hourly route/method/status tuple with fewer than five calls, before any grouping. Traffic daily totals and path/country/device/referrer summaries all apply the same rule, preventing totals from trivially exposing the withheld rows. Raw hourly aggregates remain restricted to internal service RPCs; admin readers receive only these reports. Counts therefore undercount even beyond sampling/loss. Low traffic, known visit times and repeated requests can still identify someone; this threshold is risk reduction, not k-anonymity or an anonymity guarantee. The owner-selected fix keeps suppression before aggregation to protect small cells. Traffic labels figures as views from cells with at least 5 views; Endpoints labels calls from cells with at least 5 calls. Both state “small cells hidden for privacy; totals undercount”, including views by day. These are sums of retained cells, not complete totals. Aggregate-first suppression was deliberately not adopted because it could reveal small cells through larger grouped totals.

This is a new visitor data flow. It is server-side only; no client beacon, cookie, new hostname or CSP change is introduced. No consent-banner change is claimed on that basis. The owner must confirm this conclusion and the retention wording with their privacy advice before enabling telemetry.

Proof: `adminTelemetry.test.mjs` covers disabled no-op, normalization, bounded aggregation, deferred flush, errors and SQL allowlist parity. The host runs `test-admin-panel-telemetry.mjs` for real aggregation, access, privacy, retention and replay.
