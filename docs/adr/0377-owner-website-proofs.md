# ADR-0377: Owner website proofs for dark video offers

Status: Implemented, default off; live proofs blocked on the separate Crun breaker/Seedance endpoint fix being merged and applied.

Date: 2026-11-23

The frozen owner-proof work order permits the existing administrator to exercise real website upload, signing, billing, supplier, refund and storage paths for Seedance 2.5 edit/extend and the three Crun Veo image variants. Customer availability and prices are unchanged.

`APP_RUNTIME_FLAGS.ownerProof` defaults off. Each eligible first-party request requires the middleware's verified `aal2` and a fresh database read of `users.is_admin === true`. No account identifier or client-supplied proof flag grants eligibility. OAuth client identities are excluded before the role read, including Developer API and MCP calls. Generation requests consume their existing limiter before reading the role; the verdict is reused, including template checks. Eligibility after a refusal controls diagnostic visibility only and never grants admission. Stored rate verdicts use the existing response mapping, including account controls. Non-eligible callers keep their normal responses: dark Seedance stays hidden; Veo and opened offers use their ordinary rate response. Requests rejected before the rate boundary consume no attempt. Dark quotes resolve eligibility before their normal hidden-offer refusal, then keep validation and quota checks in their original order. Seedance candidates require a valid idempotency key and no template keys. Read errors fail closed. Only the five named offers can bypass the Seedance runtime gate, inactive/gated catalog checks, and Veo variant/parity gates. For Veo this applies only to requests with source references, never ordinary text generation.

Veo capabilities are copied per request with a single image slot. Its active route, supplier/endpoint identity, stored breakers and provider admission policy remain mandatory. All existing authentication, rate, idempotency, consent, source ownership/measurement, length, moderation, spend, refund and storage rules remain in place. Proof jobs persist `inputs.owner_proof = true` and use the paid ledger path at catalog prices (including the 76/78 Seedance placeholders); a free allowance cannot substitute for the billed proof.

`GET /api/v1/owner-proof` returns only public capability projections, with `private, no-store`; ineligible callers receive 404 after the existing authentication middleware. The route is in `lib/adminRouteInventory.json`; migration 0602 extends only its telemetry allowlist. Public catalog code, cache keys and payloads are unchanged. Only Create and Library Seedance surfaces on web and phone mount the in-memory overlay. Discovery is suppressed unless the current token has aal2 and shares one in-flight request per session. It uses a silent no-store fetch that cannot refresh or clear authentication or raise auth/step-up UI. Identity/session-generation changes and sign-out invalidate pending reads. A definite 401, 403 or 404 clears private state; focus, same-session token updates, phone backgrounding and transient failures retain the last models while revalidating. Both clients retain ephemeral model/account-epoch history when a private image slot is exposed with an image already present, including Switch placement, restored drafts and carried images. If that slot disappears, Create blocks submission, offers removal, and keeps New generation available. Strict serialization is explicit only for this owner-proof path; ordinary model switches and Chat preserve their prior attachment behavior. Phone withdrawal also disables submission and offers Remove image. Phone swap scenes retain their own capability projection. Phone shared catalog promises and persistent catalog storage never see this overlay.
