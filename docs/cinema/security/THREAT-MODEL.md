# Cinema threat model

25 September 2026; lightweight STRIDE review of main `2f60cec` and planned Cinema v1.0. Required before each major feature. Existing controls are reusable evidence, not proof that the planned flow is secure. Owners below are roles to assign in each PR; no named responder is assumed.

Assets: identities/sessions, creator reputation, private drafts/evidence, media grants, entitlements, votes/rankings, cash/credit ledgers, payouts, provider credentials and audit history. Actors: viewer, subscriber, creator, moderator, finance operator, platform operator, attacker/bot, provider and service/queue worker. Boundaries are client→edge→verified identity→policy→RPC/database, direct upload→Stream→webhook, payment→webhook→ledger, and privileged UI→step-up→audited decision.

## Feature-review method

Each PR names affected T IDs, new assets/actors/entry points, permitted and forbidden actions, abuse cases, mitigations, tests and residual risk owner. Consider synchronous and queued/retried paths, concurrency, account/role revocation, provider outage and partial failure. Do not mark a threat closed from a mocked happy path alone. Link evidence in ASVS-MAPPING and record any critical/high exception in the risk decision, including expiry and compensating controls.

Before paid launch, execute the complete creator→upload→moderate→publish→subscribe→watch→vote→earn→payout journey and hostile variants. Independent DAST/API/business-logic testing is required in an isolated preview, with scope and disposable data agreed; this assessment does not run attacks against production.

## Creator onboarding increment

ADR-0049 implements controls for T02/T03/T09: private applicant statements; server-managed scoped review; fresh TOTP plus Access; active account and no self-review checks; serialized replay-safe decisions; append-only audit. The new review UI treats applicant text as plain React text. Role/status changes are checked from database state, not browser metadata. Residual risks: approver bootstrap and retention policy need an owner-approved operational decision; recent token theft within the five-minute window remains possible; signed-in deployment/Access verification and monitoring are still required before activation. No privileged role, payout permission or public film is created by signup or application submission.

## Private content increment (ADR-0050)

ADR-0050 adds private creator content (T01/T02/T03): prevent guessed parent/content IDs from crossing ownership, reject role/state/provider/money fields, serialize revisions and idempotency, limit sibling/total drafts and recheck membership before replay. SQL fixes PRIVATE/DRAFT and grants no publication or upload capability. Rights and media review remain prerequisites for a later lifecycle expansion.
