## Explicit contract exception and implementation choices

**Shared history preserves the active pattern.** `beatHistory.mjs` restores snapshots while deliberately keeping `present.currentPattern`. Consequently, a literal requirement that *every* document field, including `selectPattern`, reverses on Undo conflicts with keeping the web/N2 history behavior. Host-accepted disposition: retain shared history unchanged. Undo restores a region's pattern assignment, but preserves the active pattern selection. The picker composes `setRegionPattern` then `selectPattern` in one `apply`; both changes save, and the region edit undoes. The regression test explicitly records this exception. Making active-pattern selection undoable would require a separate authorized change to the history contract.

The shared factory defaults new documents to Song. This remains unchanged. Existing pad/grid screen tests now explicitly prepare a Pattern-view document instead of assuming the old screen ignored the document's stored view.

Narrow region blocks retain their musical width and at least 44 pt enclosing hit containers. Following N3-R4, selected regions below 88 pt omit on-block handles; inspector and accessibility actions provide trimming/resizing. Wider regions retain 24 pt handle visuals with 44 pt hit containers, with the resize target centred on the right edge. Cycle handles remain vertically staggered to avoid sharing a hit area on narrow cycles. This accommodates React Native's parent-bound hit-testing limit; actual hit testing and overlapping neighbouring regions still need device review.

The explicit prohibition on device/simulator runs overrides the general ARTEMIS-before-tests instruction. Tests exercise mocked native surfaces and deterministic handlers; there was no ARTEMIS exploration. This is not evidence of native responder feel or assistive-technology behavior.
