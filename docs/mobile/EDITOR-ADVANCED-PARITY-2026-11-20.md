## 1. Audit: what the web editor has and what the phone has (verified in code)

Web: `app/veyrnox/_components/editor/*` (73 files), pure libs `app/veyrnox/_lib/editor*.mjs`. Phone: `apps/mobile/src/components/editor/*`, model `apps/mobile/src/lib/nativeEditorModel.ts`.

Shared facts
- One validator governs every saved document: `validateSequence` (`app/veyrnox/_lib/editorSequenceValidation.mjs:51`), called by `lib/projectDocument.js:36` on `PUT /api/v1/projects/:id/document`. Clip keys l.46, text keys l.47, media keys l.48, top-level l.52. Timeline JSON <= 30,000 bytes (l.103). The phone already imports it (`apps/mobile/src/lib/editorAgentOperations.ts:3`), so the pure web libs bundle under Metro.
- The phone keeps unknown fields on load/save (`timelineOf`, `nativeEditorModel.ts:50-70`), so web-made masks, keyframes, words etc. survive, with three defects: tracks are rebuilt without `solo`; the Animation tool writes only `{in,out,duration}` and drops `combo/period/amount/offset/span` (`FullEditorScreen.tsx:443-447`); native `DEFAULT_TEXT_STYLE.strokeWidth` is 0 where the web default is 2. No test proves a web project survives a native round trip.
- Phone preview is `expo-video`/`expo-image` of one active clip plus one caption as plain text (`EditorPlayback.tsx`, `EditorMediaPreview.tsx`). It renders no filter, transform, mask, colour, text style or layer. `@shopify/react-native-skia` 2.14.0 is installed (used only by photo live edit). No reanimated, gesture-handler, ffmpeg, ML or audio-graph library. `react-native-audio-api` is proposed in open PR #2428 (not merged).
- Phone export is server render only (`useServerExport.ts`, `editorServerExport.ts`). The server translator (`lib/editorServerRenderTranslate.js:14-43`) accepts only `id mediaId in len volume transition start trackId` + `transitionType: dissolve`, centred unstyled text, video/audio media, black background, one track per kind, no overlaps. Every advanced field below is refused with `400 editor_render_unsupported {feature}`. The server runner is a third-party headless engine driven by a call plan, so widening it is not a realistic path. The web editor exports advanced edits by rendering in the browser (`editorSequenceRender.mjs`, `editorAudio.mjs`, WebCodecs via mediabunny) and uploading to `POST /api/v1/library/editor-renders` (AVC MP4 <= 25 MiB, <= 600 s, <= 4096 px; flag `libraryExports`). Phone parity therefore needs an on-device compositor, audio mix and encoder.
- `FullEditorScreen.tsx` is 512 lines (limit 500) with very long lines; the 13 tool blocks live inline in `EditorToolSheet` usage (`:390-474`). Phone controls are steppers and choice chips only: no slider, colour or font picker.
- None of the seven web tool groups calls a server or spends credits. Nothing below adds a paid or content-sending POST. If a slice ever does, it is registered in `aiConsent.ts` `CONTENT_POSTS` and `hardPaywall.ts` `PAID_ACTIONS` and tested through the real guard (`editorAiEditClient.test.ts:58-72` pattern), price shown before spend.

## 2. Decisions (host, reversible unless marked)
- D1 Authoring first. Each authoring slice writes exactly the web fields, validated with the web validators imported from `app/veyrnox/_lib` (no forked copies), so every phone edit opens unchanged on the web and vice versa. Pure web libs are imported, not ported, where they have no browser globals.
- D2 Honest intermediate state. Until the on-device renderer lands (S11), a panel whose effect the phone preview does not draw says so in one line, and server export maps `editor_render_unsupported {feature}` to a plain message naming the tool ("Phone export can't include masks yet") instead of a code. No link-outs.
- D3 On-device rendering (expensive to reverse: ADR). Preview and export draw frames with Skia (installed) using ports of the web evaluators; encoding and PCM decode go through a local Expo module (`apps/mobile/modules/editor-media`, Swift first) using AVFoundation. S9 starts with a time-boxed spike that may instead adopt a maintained Skia video-export package if it supports Expo SDK 58 and the New Architecture; the ADR records the choice. Android gets the same JS layer; the native module ships an Android stub that reports "not available on this device yet" until a Kotlin port (named follow-up, not hidden).
- D4 Export choice. With the renderer present the phone offers on-device export (free) to `POST /api/v1/library/editor-renders`; server render stays for documents it accepts. No price is computed on the phone.
- D5 Flags. Web gates (`scenes`, `clipper`, `organization`, `localInference`) are honoured from the server's own answer where the phone already learns server flags; otherwise a new `EXPO_PUBLIC_*` build flag in `apps/mobile/src/lib/editorFlag.ts` that ships off. Each slice plan names which.
- D6 Size. Every new UI lives in its own file under `apps/mobile/src/components/editor/tools/` (< 500 lines each); slice 1 brings `FullEditorScreen.tsx` under 500 lines first. Strings in new i18n area files.
- D7 Dependencies. Allowed when needed; each PR states package, version and size. None for S1-S8 (controls written in-house on React Native primitives); S9 a local Expo module; S13 Apple Translation / Speech (system frameworks); S14 MediaPipe Tasks Vision (iOS pod) plus the web's own segmentation model downloaded on first use, never bundled.

### S13 privacy decision

Automatic captions are local processing, not a new collection path. The Speech request sets `requiresOnDeviceRecognition = true`, refuses devices/locales that cannot satisfy it, and reads only a project-local audio file. Translation uses installed Apple Translation language assets and returns directly to the project document. Neither feature uploads source audio or transcript text. Therefore S13 adds no new App Store privacy-label category and no new required-reason API entry to `PrivacyInfo.xcprivacy`; the existing app manifest already declares linked Audio Data for the product's separate account-backed audio features. The final generated Info.plist still carries explicit Speech authorization copy and one microphone string naming voiceovers, Beat takes and editable captions. Config tests pin the final plugin value so another plugin cannot silently replace that wording.

## 4. Rules every slice plan carries
- Touch only `apps/mobile/**`, the slice's ADR in `docs/adr/` (0000-<slug>.md, host renumbers) and, for S1, this doc. No server, migration, wrangler or web change. Files < 500 lines. No `git add -A`. No Co-Authored-By.
- Import web pure libs from `app/veyrnox/_lib`; never duplicate validators. Every write goes through `validateSequence` before save; a refused edit shows a plain message and leaves the document unchanged.
- English strings in new area files under `apps/mobile/src/lib/i18n/messages/en/` + `node scripts/gen-en-registry.mjs`. Headings `accessibilityRole="header"`, 44 pt targets, labelled controls, slider adjustable actions, reduced motion respected.
- Tests in `apps/mobile/__tests__` that fail without the change; a round-trip test per slice proving a web-shaped document with the slice's fields survives load/edit/save with its timing intact (positions, lengths, word/keyframe frames), passes `validateSequence`, and fits the 32,768-byte document cap. A refused edit never enters state or history.
- Proof: `cd apps/mobile && npx tsc --noEmit && npx jest --ci -w 2 && node scripts/gen-en-registry.mjs --check` exits 0 (host runs it through `~/.local/bin/with-build-slot`). Native slices (S9, S11-S14) also: `npx expo prebuild --platform ios --no-install` in a scratch copy and a local `xcodebuild -jobs 2` simulator build by the host, never on the iPhone 17 Pro simulator; EAS is never used.
- Do not touch `src/app/(app)/editor/[projectId].tsx` or `EngineView.tsx` (owned by another session).

## 5. Risks
- R1 The 30,000-byte timeline cap: keyframes, curves and HSL add bytes. Each slice shows the validator's size refusal as a plain message; no compression scheme is invented.
- R2 Phone CPU for audio DSP and per-pixel effects: S11 moves pixel work to Skia shaders; DSP runs off the JS thread or in the native module if measured too slow.
- R3 Fidelity: the phone render must match the web render within tolerance; S11 adds golden-value tests on the pure evaluators and a manual side-by-side check.
- R4 Android: native slices ship an honest stub on Android until a Kotlin port.
- R5 Parallel sessions: other sessions own Music, beat editor, audio studios, native-only replacements and small gaps; none of the 8 open PRs touches the editor files today. #2428 adds `react-native-audio-api`; slices do not depend on it.
