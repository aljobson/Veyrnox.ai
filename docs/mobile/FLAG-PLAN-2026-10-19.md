# Flag plan for full parity

**Status:** Proposed 2026-10-19, read from `wrangler.jsonc`, `lib/cinema/features.js` and `tests/workerBindingBudget.test.mjs` on `main` at `a77f191f`. Production and staging were not read live; the file is the only evidence.
**Why:** full parity (owner, 2026-10-19) needs about a dozen Cinema and platform features switched on in production, and the phone cannot be tested against any of them while they are off. Both environments are out of Cloudflare text-binding room.
**Rule that stays:** flags change only on the owner's explicit words, and an assistant never flips one.

## 1. The constraint

- **Production:** `vars` is capped at 77 by `tests/workerBindingBudget.test.mjs` (81 vars plus 48 secrets was 129 bindings against Cloudflare's 128). Comments in the file say 125 of 128 are used.
- **Staging:** the file says it "is at the 128 text-binding limit"; five flags were removed on 2026-10-17 to fit store billing.
- Every flag reads `=== 'true'`, so an absent flag is off. Each new "on" flag costs a binding.

## 3. Recommended fix: consolidate, as the Editor and Publish already did

`EDITOR_RUNTIME_FLAGS` and `PUBLISH_RUNTIME_FLAGS` are single JSON variables that carry many switches in one binding. Do the same for Cinema:

1. Add `CINEMA_RUNTIME_FLAGS`, a JSON object, read by `cinemaFeatures()` next to the existing individual vars. During the change an individual var still wins, so nothing flips by accident.
2. Move the twelve Cinema and creator vars now set in production into it. That frees about ten production bindings and makes room for every later flip.
3. Do the same for staging, which also frees room there.
4. Keep `CINEMA_ENABLED` as its own var (the master switch).
5. A test pins that the consolidated form returns exactly the same `cinemaFeatures()` as the old vars for the current production and staging values.

This is a server change with a test, one PR, no flag changes. It does not turn anything on.
